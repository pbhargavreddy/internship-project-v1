- **Step 6, Groq `Tool choice is none` 400 (fixed 2026-11-21):** the agent sends no `tools`, which Groq treats as `tool_choice="none"`. gpt-oss-120b sometimes emits a native tool call anyway and Groq rejects the reply with a 400. Every agent completion now goes through `react.py::groq_final_answer`. On that 400 it logs a WARNING and retries once with "Write your final answer now in plain text…", and the plain-text reply is used as the final answer. If the retry also fails, it logs a WARNING and returns `fallback_answer()`: the paper_search papers as `[Title](url)` links, or else the latest tool results. Other errors still raise. The history is plain text, so no tool_calls flattening is needed. Live check: the 400 → retry → 200 path appeared in the backend log. A full 5-run check was blocked because arXiv, Semantic Scholar and Groq all returned 429 (each paper_search took about 3 min).
- **Step 6, agent LLM fallback chain + degraded mode (2026-11-21):** `backend/llm/chain.py`. The chain order, by default: **1. Groq `openai/gpt-oss-120b` → 2. Groq `qwen/qwen3.8-27b` → 3. Groq `openai/gpt-oss-20b` → 4. `FALLBACK_*` endpoint** (only if set; currently a second Groq account running `openai/gpt-oss-120b`, with its own quota). qwen3.8-27b replaced `llama-3.3-70b-versatile`, which returns 404 for this key; a live tool-call test confirmed qwen3.8-27b accepts `tools` on Groq. Every `ApiLLM.generate` call goes through `agent_chat()`, including `groq_final_answer`, the summarize fallback and `llm_researcher`. The chain moves to the next entry on 429, 413, 5xx, timeouts, connection errors and 404 / decommissioned model names. A 429 sets a cooldown for `Retry-After` seconds (60 s if absent), keyed by `(base_url, sha256(api_key)[:12], model)`: the same model on another account stays usable, and keys never appear in logs. SDK retries are off, so a fallback happens immediately. If every entry fails, `ReActAgent._degraded` answers instead of raising: (a) a paper-search message gets a direct `paper_search` and the Papers found table; (b) a chat with documents gets `rag_search` plus the fine-tuned model, or a Groq-free "unreachable" message; (c) anything else gets a fixed "temporarily unavailable" message. Responses carry `agent_model`, `agent_fallback` and `degraded`, and the UI shows an "Agent: <model> (fallback)" badge (compile-checked only, not seen in a browser). Live checks: an invalid first model fell through to gpt-oss-20b (`agent_fallback=True`), and all 3 degraded cases returned HTTP 200 with every model invalid.
- **Step 6, per-chat conversation memory (2026-11-21):** history was already passed to Groq: `POST /agent/chat` loads this `chat_id`'s messages from the chat store (MongoDB, or local JSON when offline) and sends past exchanges as user/assistant messages, final answers only. What changed:
  - **Limits:** history is now capped at `AGENT_HISTORY_MESSAGES=10` messages and `AGENT_HISTORY_MAX_TOKENS=3000` tokens (cl100k), dropping the oldest turns first (`memory.py::trim_history`). These replace `AGENT_HISTORY_TURNS`.
  - **Papers in history:** if a stored answer doesn't link every paper it found, the Papers found list is appended to it as numbered `[Title](url)` lines, so "the first one" can be resolved later.
  - **Standalone rewrite:** before the first `rag_search` / `summarize_papers` of a turn that has history, one short LLM call through the chain rewrites the follow-up into a standalone question (shown as a "Standalone question" note). It is skipped when there's no history and falls back to the raw message on error. The first `rag_search` of that turn uses the standalone question as its query.
  - **Fine-tuned model:** it still gets only the standalone question plus the retrieved chunks, never the history.
  - **Isolation:** history comes only from this chat, and retrieval is filtered by `chat_id`.
- **Step 6, `compare_papers` + clarification follow-ups (2026-11-21, behind `ENABLE_COMPARE=true`, default off):**
  - **`backend/agent/doc_resolver.py::resolve_docs(text, chat_id)`** returns the chat's filenames named in the text, ignoring case, `.pdf`, spaces, `-` and `_` ("Journal 1" = `journal1.pdf`; "journal 10" doesn't match `journal1.pdf`). "doc 2" / "paper 2" / "file 2" mean the chat's 2nd document in `names.json` registry order (≈ upload order).
  - **`backend/agent/compare.py::ComparePapersTool`** takes `docs` (2–3 names, optional) and `aspects` (default: objective, method, dataset, results/metrics, limitations). With no names and exactly 2 docs in the chat, it uses both. With more, it lists the filenames and sets `pending_action = {"tool": "compare_papers", "missing": "docs"}`. Per doc and aspect it retrieves the top 2 chunks from that doc only (vector + reranker fusion, filename stripped), at most 400 chars each, and `COMPARE_CONTEXT_CHARS` is split evenly between the docs. It then makes **one** chain (Groq) call for JSON `{rows, summaries, differences}`, validated with pydantic and retried once on bad JSON, and returns a clean error message after that. Python builds the Markdown table, the per-paper summaries and the "Key differences" list. It logs prompt tokens + `max_tokens` and shrinks the passages until they fit `COMPARE_TOKEN_BUDGET=6000`.
  - **Final tool:** the output is the answer as-is. It skips the 4,000-char observation cut, the agent's final-answer call and the fine-tuned model.
  - **Pending action:** stored as `Session.pending_action`, which is mirrored to `chats.pending_action` in MongoDB (or the local chat JSON) by `ChatHistorySessionStore`. The session file is the fallback if the chat store fails. On the next turn, if the message names 2+ docs, the pending tool runs directly (no rewrite, no ReAct routing). The pending action is cleared either way.
  - **Rewrite prompt** now gets the last assistant message and the chat's filenames, and is told to keep the original task verb and spell filenames out in full. **Routing guard:** with the tool enabled and 2+ docs, the (rewritten) question is checked for compare / vs / versus / difference / contrast, and a match forces `compare_papers`. When enabled, this adds the rewrite call to every turn that has history in a multi-doc chat.
